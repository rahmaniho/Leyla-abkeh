# راهنمای پنل مدیریت محتوا (Decap CMS)

پنل در نشانی `/admin/` در دسترس است. **وجود فایل‌های پیکربندی به‌معنی فعال بودن پنل نیست**؛
پنل تنها پس از فعال‌سازی Netlify Identity و Git Gateway کار می‌کند.

## ۱. فعال‌سازی (یک‌بار)

1. Netlify → Site configuration → **Identity** → Enable Identity.
2. Identity → **Services** → Git Gateway → Enable.
3. Identity → **Invite users** → ایمیل مدیر را وارد کنید و دعوت را بپذیرید.
4. در `public/admin/config.yml` مقدار `site_url` و `display_url` را با دامنهی نهایی جایگزین کنید.

پس از این مراحل: ورود به `/admin/` → ورود با ایمیل/رمز → ویرایش محتوا.

> اگر ورود انجام شد اما پنل خالی ماند یا محتوا بارگذاری نشد، معمولاً یکی از دو مورد است:
> Git Gateway فعال نشده، یا دسترسی کاربر به مخزن GitHub تنظیم نشده است.

## ۲. مسیر محتوا (بررسی‌شده)

| مورد | مقدار | بررسی |
| --- | --- | --- |
| پوشهی مقالات | `src/content/blog` | همان پوشه‌ای که `src/content/articles.ts` با `import.meta.glob` می‌خواند |
| مسیر تصاویر | `public/uploads` | Vite آن را به `dist/uploads` کپی می‌کند و با `/uploads/...` سرو می‌شود |
| نشانی عمومی تصویر | `/uploads` | مطابق `public_folder` |
| فرمت | Markdown با Front Matter | با پارسر داخلی (`parseFrontMatter`) خوانده می‌شود |
| نشانی مقاله | `/articles/<slug>` | از فیلد `slug` یا نام فایل |

> **مهم:** اگر پوشهی محتوا یا مسیر تصاویر را تغییر دادید، باید هم `config.yml` و هم
> `src/content/articles.ts` (برای محتوا) یا `vite.config.ts` (برای تصاویر) هم‌زمان به‌روزرسانی شوند.

## ۳. فیلدهای هر مقاله

| فیلد | نام | الزامی | توضیح |
| --- | --- | --- | --- |
| عنوان | `title` | ✓ | H1 صفحه و عنوان پیش‌فرض سئو |
| نشانی یکتا | `slug` | – | حروف لاتین کوچک، رقم و خط تیره |
| خلاصه | `description` | ✓ | فهرست مقالات و توضیح متای پیش‌فرض |
| متن | `body` | ✓ | Markdown؛ HTML خام خنثی می‌شود |
| تصویر شاخص | `cover` | – | برای OG و بالای مقاله |
| نویسنده | `author` | – | پیش‌فرض: «دفتر وکالت لیلا آبکه» |
| تاریخ انتشار | `publishDate` | ✓ | ISO |
| آخرین بازبینی | `lastReviewed` | – | در Schema و صفحه نمایش داده می‌شود |
| پیش‌نویس | `draft` | – | `true` → منتشر نمی‌شود |
| عنوان سئو | `seoTitle` | – | حداکثر ~۶۰ نویسه |
| توضیح متا | `metaDescription` | – | حداکثر ~۱۵۵ نویسه |
| برچسب‌ها | `tags` | – | فهرست |
| حوزه‌های مرتبط | `relatedServices` | – | برای لینک‌سازی داخلی |

## ۴. گردش‌کار انتشار

`publish_mode: editorial_workflow` فعال است: پیش‌نویس → «در حال بازبینی» → انتشار.
هر انتشار یک کامیت در شاخهی `main` ایجاد می‌کند و Netlify به‌طور خودکار بیلد و deploy می‌کند.
تا پایان بیلد، تغییرات در سایت دیده نمی‌شوند (معمولاً کمتر از دو دقیقه).

## ۵. محدودیت‌ها و نکات

- Markdown از نوع GFM پشتیبانی می‌شود (جدول، فهرست، نقل‌قول).
- درج HTML خام در متن مقاله خنثی (escape) می‌شود؛ برای ویدئو یا iframe باید از افزونه/دستکاری مستقیم کد استفاده شود.
- تصاویر آپلودی بهینه‌سازی خودکار نمی‌شوند؛ پیش از آپلود، عرض حداکثر ۱۲۰۰ پیکسل و فرمت WebP/JPEG توصیه می‌شود.
- در صورت تغییر CSP (`netlify.toml`)، مطمئن شوید میزبان‌های `unpkg.com` و `identity.netlify.com` مجاز بمانند، وگرنه پنل بارگذاری نمی‌شود.
- اگر پنل در محیط جدید باز نشد، ابتدا کنسول مرورگر را برای خطای CSP بررسی کنید.
