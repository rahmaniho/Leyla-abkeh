# پنل مدیریت سایت (وب‌اپ مدیریت محتوا)

> پنل مدیریت سایت «دفتر وکالت لیلا آبکه» یک **وب‌اپ (PWA) مستقل** است که روی `/admin/` سرو می‌شود؛
> می‌توانید آن را روی گوشی یا دسکتاپ **نصب** کنید (مثل یک اپلیکیشن واقعی).
> زیرساخت: **Decap CMS** (ویرایش محتوا) + **Netlify Identity** (احراز هویت) + **Git Gateway** (نوشتن در مخزن).
> هیچ سرور یا پایگاه‌دادهٔ جدا لازم نیست؛ هر انتشار یک کامیت در GitHub می‌سازد و Netlify خودکار دیپلوی می‌کند.

---

## ۱) معماری و مدل امنیتی

| لایه | نقش | جزئیات |
| --- | --- | --- |
| `noindex` + `no-store` | دیده نشدن و کش نشدن پنل | هدرهای `X-Robots-Tag` و `Cache-Control` در `netlify.toml` برای `/admin/*` |
| **Netlify Identity** | احراز هویت مدیر | ایمیل/رمز؛ هیچ حسابی بدون دعوت ساخته نمی‌شود |
| **Git Gateway** | نگاشت هویت به دسترسی GitHub | بدون نیاز به توکن شخصی در مرورگر |
| **Decap CMS** | ویرایشگر حرفه‌ای محتوا | Markdown + پیش‌نویس → بازبینی → انتشار (Editorial Workflow) |
| **CSP اختصاصی** | محدودسازی منابع مجاز | فقط `self`، `unpkg.com`، `identity.netlify.com` و دامنه‌های Git Gateway/API نتلیفای |
| **همه‌چیز در Git** | تاریخچه و بازیابی | هر تغییر یک کامیت؛ بازگشت = `git revert` یک کامیت |

- نشانی پنل در sitemap نیست؛ در `robots.txt` مسیر `/admin/` رد می‌شود.
- هیچ کلید محرمانه‌ای در فرانت‌اند یا مخزن نیست (`TELEGRAM_BOT_TOKEN` و امثال آن فقط در env نتلیفای هستند).
- نشست ورود با کوکی‌های Netlify Identity مدیریت می‌شود؛ اشتراک‌گذاری رمز = اشتراک‌گذاری کل دسترسی — برای هر مدیر یک حساب جدا تعریف کنید.

## ۲) راه‌اندازی اولیه (فقط یک‌بار، حدود ۵ دقیقه)

1. Netlify → سایت → **Identity** → **Enable Identity**.
2. Identity → **Services** → **Git Gateway** → **Enable**.
3. Identity → **Invite users** → ایمیل مدیر را وارد کنید → ارسال دعوت.
4. در ایمیل، روی لینک دعوت بزنید → رمز خود را تعیین کنید → وارد `https://leyla-abkeh.ir/admin/` شوید.
5. (پیشنهادی) اطلاعات سایت در `src/config/site.ts` و موارد تأییدنشده در `src/config/verification.json` را با مالک چک کنید.

> اگر «Invite» با موفقیت ارسال شد ولی مدیر آن را پیدا نکرد: پوشهٔ اسپم را چک کنید؛
> اگر ایمیل دعوت هرگز نمی‌رسد، در Identity → Invite users همان آدرس را دوباره دعوت کنید
> (یک حساب جدید می‌سازد، نه تکراری).

## ۳) نصب به‌عنوان اپلیکیشن روی گوشی (PWA)

پنل یک وب‌اپ کامل است: آیکن اختصاصی، تمام‌صفحه، سریع و بدون نوار مرورگر.

**اندروید (Chrome):**
1. `https://leyla-abkeh.ir/admin/` را باز کنید.
2. منوی ⋮ → **افزودن به صفحهٔ اصلی** (یا بنر «Install app» که خودکار ظاهر می‌شود) → نصب.
3. آیکن **«مدیریت سایت»** در صفحهٔ اصلی اضافه می‌شود.

**آیفون (Safari):**
1. `https://leyla-abkeh.ir/admin/` را در **Safari** باز کنید.
2. دکمهٔ اشتراک‌گذاری (مربع با فلش) → **Add to Home Screen / افزودن به صفحهٔ اصلی** → افزودن.

**دسکتاپ (Chrome/Edge):** آیکن نصب (⊕ یا مانیتور) در نوار آدرس — یا دکمهٔ «نصب «مدیریت سایت» روی این دستگاه» داخل پانل «راهنمای مدیر».

> پس از نصب، باز کردن آیکن مستقیماً پنل را تمام‌صفحه باز می‌کند؛ تجربه مثل یک اپ نیتیو است.
> دکمهٔ شناور **«؟ راهنمای مدیر»** در پایین پنل همیشه در دسترس است: راهنمای نصب، راه‌اندازی، گردش‌کار و لینک‌ها.

## ۴) گردش‌کار انتشار محتوا (روزنامه‌ای)

1. «مقالات» → **مقالهٔ جدید** → پر کردن فرم (عنوان، خلاصه، متن، تصویر شاخص…) → **ذخیره به‌عنوان پیش‌نویس**.
2. پس از بازبینی (لحن، حقوقی، تصویر، لینک‌های داخلی) → **«Ready for review»**.
3. کسی که حق انتشار دارد (همان مدیر) → **Publish** → یک کامیت روی `main` ساخته می‌شود.
4. Netlify به‌طور خودکار بیلد و منتشر می‌کند (معمولاً < ۲ دقیقه). پیش‌نمایش انتشار روی همان PR/Preview لینک Netlify دیده می‌شود.
5. تصمیم با شماست: منتظر بمانید یا صفحهٔ مقاله را یک بار رفرش کنید و تحویل را ببینید.

**قواعد محتوا (اجرای خودکار در بیلد):**
- پیش‌نویس‌ها (`draft: true`) منتشر نمی‌شوند.
- تصویر شاخص و تصاویر داخل متن باید در `public/images/...` باشند و نام‌گذاری استاندارد داشته باشند (`-cover`، `-1200`، نسخه‌های `-640`) تا srcset خودکار ساخته شود.
- فایل‌های بارگذاری‌شده از پنل در `public/uploads/` می‌نشینند و با `/uploads/…` سرو می‌شوند.
- به‌جای نام تکراری وکیل در عنوان‌ها از `{{lawyer.professionalTitle}}` استفاده کنید (جایگزینی خودکار).

## ۵) نقش‌ها و سطح دسترسی — واقعیت فنی

نکتهٔ مهم فنی: در این معماری (Netlify Identity + Git Gateway) **هر کسی که وارد پنل قابل انتشار دعوت شود می‌تواند دکمهٔ Publish را بزند** و یک کامیت روی `main` بسازد. `editorial_workflow` یک گردش‌کار فرآیند است، نه یک دیوار فنی.

| وضعیت مطلوب | راه‌حل |
| --- | --- |
| فقط مدیر سایت (وکیل) محتوا می‌سازد | همین معماری فعلی — ساده‌ترین و امن‌ترین حالت |
| نویسندهٔ بیرونی می‌خواهید ولی نمی‌خواهید منتشر کند | او را در Identity دعوت نکنید؛ محتوای آماده (Markdown + front matter) را به مدیر تحویل دهد و مدیر آپلود کند؛ یا از Pull Request در GitHub استفاده کنید (نویسنده در شاخهٔ خودش؛ مدیر merge می‌کند) |
| دو مدیر هم‌سطح | هر دو دعوت می‌شوند؛ گردش‌کار بازبینی (پیش‌نویس → آماده → انتشار) همچنان رعایت می‌شود |

> اگر واقعاً «نویسندهٔ فقط پیش‌نویس» سخت‌افزاری لازم شد، آن‌وقت باید به سراغ یک CMS با نقش‌های واقعی (مثلاً سرویس میزبانی‌شده یا بک‌اند اختصاصی) رفت؛ برای دفتری که یک نفر محتوا را اداره می‌کند، همین معماری کفایت می‌کند.

## ۶) امنیت و نگهداری

- **رمزها:** هرگز در کد/چت/ایمیل نفرستید. دعوت‌ها فقط به ایمیل رسمی ارسال شود.
- **لاگین مشترک ممنوع** — هر نفر یک حساب.
- **خروج از حساب** در گوشهٔ پنل (بالا-چپ) موجود است؛ روی دستگاه مشترک حتماً خارج شوید.
- **به‌روزرسانی Decap:** نسخه در `public/admin/index.html` قفل است (`decap-cms@3.17.1`)؛ ارتقا = تغییر همین عدد + تست `/admin/` + یک PR.
- **بازگردانی:** همه‌چیز Git است — `git revert <sha>` یا از GitHub → Commits → بازگردانی آن کامیت؛ Netlify خودکار دوباره منتشر می‌کند.
- **پشتیبان:** خودِ مخزن پشتیبان است؛ افزون‌بر آن می‌توانید هفتگی/ماهانه یک clone از ریپو بگیرید.

## ۷) عیب‌یابی رایج

| نشانه | علت احتمالی | راه‌حل |
| --- | --- | --- |
| صفحهٔ سفید/خالی پنل | Git Gateway فعال نیست / ویجت Identity بارگذاری نمی‌شود | بخش ۲ را انجام دهید؛ Console را چک کنید؛ فایروال/CDN را موقتاً خاموش کنید |
| «Error loading the CMS configuration» | خطای YAML در `public/admin/config.yml` | فایل را در ویرایشگر YAML اعتبارسنجی کنید؛ کامنت‌ها و تورفتگی‌ها |
| دعوت‌نامه نمی‌رسد | ایمیل اشتباه/اسپم | پوشهٔ اسپم؛ دعوت مجدد با همان آدرس |
| مقاله منتشر نمی‌شود | بیلد قرمز / draft روشن | لاگ Deploy در Netlify؛ فیلد «پیش‌نویس» را خاموش کنید |
| تصویر بارگذاری نمی‌شود | حجم > ۱۰ مگابایت یا مسیر اشتباه | تصویر را فشرده کنید؛ مسیر `/uploads/…` باید در دسترس باشد |
| پنل بعد از نصب باز نمی‌شود | کش کهنهٔ PWA | یک بار از مرورگر `/admin/` را عادی باز کنید؛ نسخهٔ کش SW را با تغییر `VERSION` در `public/admin/sw.js` می‌توان‌گذاری کرد |
| «Git Gateway error» پس از login | دسترسی repo کافی نیست | GitHub → Settings → Collaborators: به مدیر دسترسی Write بدهید |

## ۸) چک‌لیست «راه‌اندازی و تحویل» (برای بار اول)

- [ ] Identity فعال شد · Git Gateway فعال شد · مدیر دعوت و وارد شد
- [ ] `/admin/` روی گوشی مدیر «نصب» شد (PWA)
- [ ] یک مقالهٔ آزمایشی به‌عنوان پیش‌نویس ساخته و منتشر شد؛ اصلاح/حذف آن با `git revert` تمرین شد
- [ ] sitemap پس از اولین انتشار بررسی شد (`/sitemap.xml`)
- [ ] زمان پاسخ و مشکلات را با نصب‌کنندگان واقعی (۲–۳ نفر) تست کردید

## ۹) مرجع فنی — مسیرها، فیلدها و محدودیت‌ها

| مورد | مقدار | بررسی |
| --- | --- | --- |
| پوشۀ مقالات | `src/content/blog` | همان پوشه‌ای که `src/content/articles.ts` با `import.meta.glob` می‌خواند |
| مسیر تصاویر | `public/uploads` | Vite آن را به `dist/uploads` کپی می‌کند و با `/uploads/...` سرو می‌شود |
| نشانی عمومی تصویر | `/uploads` | مطابق `public_folder` |
| فرمت | Markdown با Front Matter | با پارسر داخلی (`parseFrontMatter`) خوانده می‌شود |
| نشانی مقاله | `/articles/<slug>` | از فیلد `slug` یا نام فایل |

> اگر پوشۀ محتوا یا مسیر تصاویر را تغییر دادید، باید هم `config.yml` و هم
> `src/content/articles.ts` (برای محتوا) یا `vite.config.ts` (برای تصاویر) هم‌زمان به‌روزرسانی شوند.

**فیلدهای هر مقاله:**

| فیلد | نام | الزامی | توضیح |
| --- | --- | --- | --- |
| عنوان | `title` | ✓ | H1 صفحه و عنوان پیش‌فرض سئو |
| نشانی یکتا | `slug` | – | حروف لاتین کوچک، رقم و خط تیره |
| خلاصه | `description` | ✓ | فهرست مقالات و توضیح متای پیش‌فرض |
| متن | `body` | ✓ | Markdown؛ HTML خام خنثی می‌شود |
| تصویر شاخص | `cover` | – | برای OG و بالای مقاله |
| نویسنده | `author` | – | پیش‌فرض: «دفتر وکالت لیلا آبکه» |
| تاریخ انتشار | `publishDate` | ✓ | ISO |
| آخرین بازبینی | `lastReviewed` | – | در Schema و صفحه نمایش داده می‌شود |
| پیش‌نویس | `draft` | – | `true` → منتشر نمی‌شود |
| عنوان سئو | `seoTitle` | – | حداکثر ~۶۰ نویسه |
| توضیح متا | `metaDescription` | – | حداکثر ~۱۵۵ نویسه |
| برچسب‌ها | `tags` | – | فهرست |
| حوزه‌های مرتبط | `relatedServices` | – | برای لینک‌سازی داخلی |

- Markdown از نوع GFM پشتیبانی می‌شود (جدول، فهرست، نقل‌قول).
- درج HTML خام در متن مقاله خنثی (escape) می‌شود.
- تصاویر آپلودی بهینه‌سازی خودکار نمی‌شوند؛ پیش از آپلود، عرض حداکثر ۱۲۰۰ پیکسل و فرمت WebP/JPEG توصیه می‌شود.
- در صورت تغییر CSP (`netlify.toml`)، میزبان‌های `unpkg.com` و `identity.netlify.com` باید مجاز بمانند، وگرنه پنل بارگذاری نمی‌شود.
- `publish_mode: editorial_workflow` فعال است؛ `site_url` و `display_url` در `config.yml` روی دامنهٔ نهایی تنظیم شده‌اند.

## ۱۰) فایل‌های مربوطه
