# داشبورد مدیریت سایت (Vercel + Supabase)

> از نسخهٔ «داشبورد»، مدیریت سایت یک **اپلیکیشن وب جدا** است که روی **Vercel** مستقر می‌شود و داده‌های پویا (مشاوره‌ها، نظرات) را در **Supabase** نگه می‌دارد.
> سایت عمومی (leyla-abkeh.ir) استاتیک روی **Netlify** می‌ماند و تغییری نمی‌کند.

## معماری

| بخش | محل استقرار | نقش |
| --- | --- | --- |
| سایت عمومی (استاتیک، ۶۷ صفحه) | Netlify | بازدیدکنندگان؛ سئو؛ مقالات (Markdown در Git) |
| فرم مشاوره → `/api/consultation` | Netlify Function | اعتبارسنجی + محدودیت نرخ + Turnstile → ذخیره در Supabase + اعلان تلگرام/ایمیل |
| بخش نظرات زیر مقالات | سایت عمومی + Supabase | خواندن تأییدشده‌ها؛ درج فقط «در انتظار تأیید» |
| **داشبورد مدیریت** (`apps/admin`) | **Vercel** | ورود (Supabase Auth)، CRM مشاوره‌ها، صف تأیید نظرات، افزودن مقاله، اعلان‌ها، گزارش‌ها |
| پایگاه داده | **Supabase** (پروژهٔ `leyla-abkeh`) | جدول‌های `consultations`، `comments`، `admin_notifications`، `visit_stats` + RPC امن `submit_consultation` و `record_visit` |
| شمارش بازدید | Netlify Function + Supabase | بیکن بی‌نام (`/api/visit`) — فقط `pathname`؛ بدون کوکی/شناسه؛ تجمیع روزانه |

چرا این معماری «حرفه‌ای» است؟
- **بدون هیچ کلید محرمانه در فرانت‌اند یا مخزن.** فرم سایت با RPC از نوع `security definer` فقط INSERT می‌زند؛ داشبورد با نشست کاربر و **RLS** کار می‌کند.
- **مشاوره‌ها** فقط برای حساب مدیر قابل خواندن هستند (هیچ سیاست anon وجود ندارد).
- **نظرات** زیر مقالات: عموم فقط «تأییدشده»ها را می‌بینند؛ هر نظری اول در صف تأیید می‌نشیند.
- **مقالات در Git می‌مانند** (منبع حقیقت؛ تاریخچه؛ بازگشت با یک کامیت)؛ داشبورد با «افزودن مقاله» یک کامیت روی `main` می‌سازد و Netlify خودکار منتشر می‌کند.
- سایت عمومی استاتیک و سریع می‌ماند؛ هیچ وابستگی دیتابیس به مسیر عمومی اضافه نشده است.

## راه‌اندازی یک‌بار (کاری که فقط مدیر می‌تواند انجام دهد)

1. **ساخت حساب مدیر در Supabase** (تا این لحظه هیچ کاربری وجود ندارد و ثبت‌نام عمومی هم غیرفعال است):
   - Supabase → پروژهٔ `leyla-abkeh` → **Authentication → Users → Add user** → ایمیل و گذرواژهٔ مدیر را وارد کنید (تیک Auto Confirm را بزنید).
2. **Netlify → Site configuration → Environment variables** را تنظیم کنید (برای ذخیرۀ مشاوره‌ها و نمایش نظرات):
   - `SUPABASE_URL` = `https://xobowqanviucymqampre.supabase.co`
   - `SUPABASE_ANON_KEY` = کلید anon (عمومی است؛ از همین سند بخش بالا یا از Supabase → Project Settings → API بردارید)
   - `VITE_SUPABASE_URL` و `VITE_SUPABASE_ANON_KEY` = همان دو مقدار (برای بخش نظرات عمومی؛ در زمان بیلد جاسازی می‌شوند)
   - بدون این متغیرها: سایت و فرم مثل قبل کار می‌کنند؛ مشاوره‌ها فقط با تلگرام/ایمیل اطلاع‌رسانی می‌شوند و بخش نظرات پنهان است.
3. (اختیاری — افزودن مقاله از داشبورد) **GitHub → Settings → Developer settings → Fine-grained tokens → Generate**: فقط ریپازیتوری `Leyla-abkeh`، دسترسی `Contents: Read and write`. سپس **Vercel → پروژهٔ leyla-abkeh-admin → Settings → Environment Variables** → افزودن `GITHUB_TOKEN` با همان توکن (نوع Sensitive).
   - بدون این توکن: صفحهٔ «مقالات» فقط فهرست را نشان نمی‌دهد و فرم افزودن به شما راهنما می‌دهد؛ همه‌چیزهای دیگر کار می‌کند.
4. (اختیاری) دامنهٔ اختصاصی برای داشبورد، مثل `admin.leyla-abkeh.ir`: Vercel → Settings → Domains → Add `admin.leyla-abkeh.ir` و CNAME مربوطه در Netlify DNS.

## ظاهر و چیدمان (نسخهٔ ۲ پنل)

پنل با سیستم طراحی «روشن مدرن + لهجهٔ طلایی برند» بازطراحی شد: سایدبار راست‌چین با گروه‌های «منوی اصلی» و «مدیریت» (اعلان‌ها با شمار خوانده‌نشده)، نوار بالای مات با چیپ سایت زنده و زنگوله، کارت‌های KPI با آیکون و دلتای ۳۰ روزه و اسپارک‌لاین، نمودار ناحیه‌ای نرم و دونات برای توزیع نظرات، آواتار حروف اول برای هر مخاطب، و صفحهٔ ورود دو ستونه. همهٔ صفحات (داشبورد، مشاوره، نظرات، مقالات، اعلان‌ها، گزارش‌ها و ورود) یکپارچه هستند.

## استفادهٔ روزانه

1. `https://…vercel.app/login` → ایمیل و گذرواژهٔ مدیر.
2. **داشبورد** (`/`): KPI های زنده با دلتای ۳۰ روز اخیر نسبت به ۳۰ روز قبل (درخواست‌های مشاوره، دیدگاه‌های در انتظار تأیید، بازدید سایت)، نمودار روند بازدید ۳۰ روز اخیر، پربازدیدترین صفحه‌ها، تایم‌لاین فعالیت‌های اخیر و کارت «رویدادهای تازه».
3. **زنگولهٔ اعلان** در نوار بالا: با هر رویداد تازهٔ سایت (درخواست مشاورهٔ جدید، دیدگاه جدید) به‌روز می‌شود؛ صفحهٔ **اعلان‌ها** (`/notifications`) فهرست کامل را دارد با دکمهٔ «همه را خوانده کن» و لینک مستقیم به ابزار مربوطه.
4. **درخواست‌های مشاوره** (`/consultations`): تغییر وضعیت (جدید ← در حال پیگیری ← انجام‌شده/لغوشده) و یادداشت داخلی هر درخواست.
5. **نظرات** (`/comments`): صف «در انتظار تأیید» ← تأیید و انتشار / رد / حذف. تأییدشده‌ها فوراً زیر مقاله نمایش داده می‌شوند.
6. **مقالات** (`/articles`): «افزودن مقالهٔ جدید» — پیش‌نویس یا انتشار مستقیم؛ با کامیت خودکار روی `main`، Netlify بیلد می‌کند.
7. **گزارش‌ها** (`/reports`): بازه‌های ۷/۳۰/۹۰ روز اخیر یا بازهٔ دلخواه؛ آمار مشاوره (کل/جدید/در حال پیگیری/انجام‌شده/لغوشده + روند روزانهٔ نموداری + موضوعات پرتکرار)، آمار نظرات (در انتظار/تأییدشده/ردشده)، آمار بازدید (روند روزانه + پربازدیدترین صفحه‌ها + سهم هر صفحه) و تعداد مقالات (در صورت پیکربندی `GITHUB_TOKEN`). خروجی **CSV با BOM** برای Excel فارسی و **چاپ/PDF** با طرح‌بندی ویژهٔ چاپ.

## اعلان‌ها (نوتیفیکیشن داخل پنل)

- جدول `admin_notifications` با سیاست RLS «فقط کاربران واردشده»؛ درج فقط از طریق تریگرهای دیتابیس انجام می‌شود.
- هر `INSERT` در جدول‌های `consultations` و `comments` به‌صورت خودکار یک اعلان می‌سازد (تریگرهای `trg_notify_consultation` و `trg_notify_comment`).
- این طرح «push به بیرون» نیست: هیچ تلگرام/ایمیلی فرستاده نمی‌شود مگر اینکه مالک تصمیم بگیرد آن‌ها را اضافه کند (کانال‌های آماده در `netlify/functions/consultation.mjs` وجود دارند اما غیرفعال‌اند).
- زنگوله هر ۴۵ ثانیه polling می‌کند؛ خوانده‌شدن اعلان‌ها با `UPDATE read=true` (یا دکمهٔ «همه را خوانده کن») ثبت می‌شود.

## گزارش‌ها (`/reports`)

- همهٔ آمار از دادهٔ واقعی Supabase در بازهٔ انتخابی محاسبه می‌شود؛ هیچ عدد ساختگی یا تخمینی درج نمی‌شود.
- خروجی CSV شامل خلاصهٔ شاخص‌ها + آمار روزانه + پربازدیدترین صفحه‌ها + موضوعات مشاوره است؛ فایل با BOM ذخیره می‌شود تا در Excel فارسی درست باز شود.
- دکمهٔ «چاپ / PDF» برگ‌مانع A4 با سربرگ دفتر تولید می‌کند (بدون نوار ناوبری و دکمه‌ها).

## شمارش بی‌نام بازدید

جزئیات کامل در `docs/VISITORS.md`. خلاصه: جدول `visit_stats(day, path, views)` فقط «تعداد نمایش مسیر در روز» را نگه می‌دارد؛ بدون کوکی، IP یا شناسهٔ دستگاه؛ مسیر `/admin*` و `/api*` شمارش نمی‌شود. شمارنده از زمان انتشار این نسخه فعال است و دادهٔ تاریخی ندارد.

## نصب به‌عنوان اپلیکیشن (PWA)

داشبورد یک وب‌اپ است؛ در اندروید/iOS از منوی مرورگر «افزودن به صفحهٔ اصلی» بزنید.
آیکن «مدیریت سایت» کنار برنامه‌ها می‌نشیند و تمام‌صفحه باز می‌شود.

## امنیت

- `disable_signup` فعال است؛ فقط حساب‌هایی که در Supabase ساخته‌اید می‌توانند وارد شوند.
- RLS: جدول `consultations` هیچ سیاست عمومی ندارد (فقط مدیر)؛ `comments` فقط خواندن تأییدشده/درج «pending» برای عموم.
- جدول‌های `admin_notifications` و `visit_stats`: خواندن/به‌روزرسانی فقط برای کاربران واردشده (پنل)؛ درج در اعلان‌ها فقط با تریگر و افزایش شماری بازدید فقط با RPC امن `record_visit`.
- API داخلی `/api/articles` دیگر بی‌نیاز از ورود فراخوانی نمی‌شود: همهٔ ورودی‌ها نیازمند Bearer token نشست Supabase هستند (بررسی با `auth.getUser` سمت سرور).
- کلید service_role هیچ‌جا استفاده نمی‌شود؛ اگر روزی لاگ یا key درز کرد، از Supabase → Project Settings → API می‌توانید آن را rotate کنید.
- داشبورد `noindex` است و در سایتمالپ/robots سایت نیست.
