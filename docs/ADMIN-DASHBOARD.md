# داشبورد مدیریت سایت (Vercel + Supabase)

> از نسخهٔ «داشبورد»، مدیریت سایت یک **اپلیکیشن وب جدا** است که روی **Vercel** مستقر می‌شود و داده‌های پویا (مشاوره‌ها، نظرات) را در **Supabase** نگه می‌دارد.
> سایت عمومی (leyla-abkeh.ir) استاتیک روی **Netlify** می‌ماند و تغییری نمی‌کند.

## معماری

| بخش | محل استقرار | نقش |
| --- | --- | --- |
| سایت عمومی (استاتیک، ۶۷ صفحه) | Netlify | بازدیدکنندگان؛ سئو؛ مقالات (Markdown در Git) |
| فرم مشاوره → `/api/consultation` | Netlify Function | اعتبارسنجی + محدودیت نرخ + Turnstile → ذخیره در Supabase + اعلان تلگرام/ایمیل |
| بخش نظرات زیر مقالات | سایت عمومی + Supabase | خواندن تأییدشده‌ها؛ درج فقط «در انتظار تأیید» |
| **داشبورد مدیریت** (`apps/admin`) | **Vercel** | ورود (Supabase Auth)، CRM مشاوره‌ها، صف تأیید نظرات، افزودن مقاله |
| پایگاه داده | **Supabase** (پروژهٔ `leyla-abkeh`) | جدول‌های `consultations` و `comments` + RPC امن `submit_consultation` |

چرا این معماری «حرفه‌ای» است؟
- **بدون هیچ کلید محرمانه در فرانت‌اند یا مخزن.** فرم سایت با RPC از نوع `security definer` فقط INSERT می‌زند؛ داشبورد با نشست کاربر و **RLS** کار می‌کند.
- **مشاوره‌ها** فقط برای حساب مدیر قابل خواندن هستند (هیچ سیاست anon وجود ندارد).
- **نظرات** زیر مقالات: عموم فقط «تأییدشده»ها را می‌بینند؛ هر نظری اول در صف تأیید می‌نشیند.
- **مقالات در Git می‌مانند** (منبع حقیقت؛ تاریخچه؛ بازگشت با یک کامیت)؛ داشبورد با «افزودن مقاله» یک کامیت روی `main` می‌سازد و Netlify خودکار منتشر می‌کند.
- سایت عمومی استاتیک و سریع می‌ماند؛ هیچ وابستگی دیتابیس به مسیر عمومی اضافه نشده است.

## راه‌اندازی یک‌بار (کاری که فقط مدیر می‌تواند انجام دهد)

1. **ساخت حساب مدیر در Supabase** (تا این لحظه هیچ کاربری وجود ندارد و ثبت‌نام عمومی هم غیرفعال است):
   - Supabase → پروژهٔ `leyla-abkeh` → **Authentication → Users → Add user** → ایمیل و گذرواژهٔ مدیر را وارد کنید (تیک Auto Confirm را بزنید).
2. **Netlify → Site configuration → Environment variables** را تنظیم کنید (برای ذخیرۀ مشاوره‌ها و نمایش نظرات):
   - `SUPABASE_URL` = `https://xobowqanviucymqampre.supabase.co`
   - `SUPABASE_ANON_KEY` = کلید anon (عمومی است؛ از همین سند بخش بالا یا از Supabase → Project Settings → API بردارید)
   - `VITE_SUPABASE_URL` و `VITE_SUPABASE_ANON_KEY` = همان دو مقدار (برای بخش نظرات عمومی؛ در زمان بیلد جاسازی می‌شوند)
   - بدون این متغیرها: سایت و فرم مثل قبل کار می‌کنند؛ مشاوره‌ها فقط با تلگرام/ایمیل اطلاع‌رسانی می‌شوند و بخش نظرات پنهان است.
3. (اختیاری — افزودن مقاله از داشبورد) **GitHub → Settings → Developer settings → Fine-grained tokens → Generate**: فقط ریپازیتوری `Leyla-abkeh`، دسترسی `Contents: Read and write`. سپس **Vercel → پروژهٔ leyla-abkeh-admin → Settings → Environment Variables** → افزودن `GITHUB_TOKEN` با همان توکن (نوع Sensitive).
   - بدون این توکن: صفحهٔ «مقالات» فقط فهرست را نشان نمی‌دهد و فرم افزودن به شما راهنما می‌دهد؛ همه‌چیزهای دیگر کار می‌کند.
4. (اختیاری) دامنهٔ اختصاصی برای داشبورد، مثل `admin.leyla-abkeh.ir`: Vercel → Settings → Domains → Add `admin.leyla-abkeh.ir` و CNAME مربوطه در Netlify DNS.

## استفادهٔ روزانه

1. `https://…vercel.app/login` → ایمیل و گذرواژهٔ مدیر.
2. **داشبورد**: تعداد درخواست‌های جدید، در حال پیگیری، نظرات در انتظار تأیید.
3. **درخواست‌های مشاوره**: تغییر وضعیت (جدید ← در حال پیگیری ← انجام‌شده/لغوشده) و یادداشت داخلی هر درخواست.
4. **نظرات**: صف «در انتظار تأیید» ← تأیید و انتشار / رد / حذف. تأییدشده‌ها فوراً زیر مقاله نمایش داده می‌شوند.
5. **مقالات**: «افزودن مقالهٔ جدید» — پیش‌نویس یا انتشار مستقیم؛ با کامیت خودکار روی `main`، Netlify بیلد می‌کند.

## نصب به‌عنوان اپلیکیشن (PWA)

داشبورد یک وب‌اپ است؛ در اندروید/iOS از منوی مرورگر «افزودن به صفحهٔ اصلی» بزنید.
آیکن «مدیریت سایت» کنار برنامه‌ها می‌نشیند و تمام‌صفحه باز می‌شود.

## امنیت

- `disable_signup` فعال است؛ فقط حساب‌هایی که در Supabase ساخته‌اید می‌توانند وارد شوند.
- RLS: جدول `consultations` هیچ سیاست عمومی ندارد (فقط مدیر)؛ `comments` فقط خواندن تأییدشده/درج «pending» برای عموم.
- کلید service_role هیچ‌جا استفاده نمی‌شود؛ اگر روزی لاگ یا key درز کرد، از Supabase → Project Settings → API می‌توانید آن را rotate کنید.
- داشبورد `noindex` است و در سایتمالپ/robots سایت نیست.
