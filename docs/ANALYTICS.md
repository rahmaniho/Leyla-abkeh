# سنجش رفتار — طرح حریم‌خصوصی‌محور

سایت **هیچ ابزار تحلیلی خارجی** (Google Analytics، Yandex، پیکسل تبلیغاتی و مانند آن) ندارد.
یک لایۀ سبک و بی‌نام در `src/lib/analytics.ts` وجود دارد که **به‌صورت پیش‌فرض خاموش** است.

## روشن‌کردن

```bash
# .env یا متغیر محیطی بیلد
VITE_ANALYTICS_ENDPOINT=https://…   # هر گیرنده‌ای که POST JSON را می‌پذیرد
# VITE_ANALYTICS_DEBUG=1            # فقط برای دیدن رویدادها در کنسول
```

بدون این متغیر، `track()` هیچ درخواستی نمی‌فرستد (تنها یک no-op است).

## رویدادها

| رویداد | چه زمانی | ویژگی‌های مجاز |
| --- | --- | --- |
| `page_view` | تغییر مسیر | `path` |
| `cta_click` | کلیک روی CTA اصلی/شناور/هدر | `location`, `target` |
| `form_start` | اولین تایپ در فرم مشاوره | `path` |
| `form_submit` | تلاش برای ارسال | `topic` |
| `form_success` | ثبت واقعی در سرور | `topic` |
| `form_validation_error` | خطای اعتبارسنجی | `field` (بدون مقدار) |
| `form_rate_limited` | محدودیت نرخ | — |
| `form_unavailable` | نبود سرور/پیکربندی | — |

## قواعد سخت

- فقط کلیدهای فهرست سفید عبور می‌کنند: `path, location, target, topic, field, status, reason, channel`.
- هر مقدار به ۶۴ نویسه بریده می‌شود؛ متن آزاد کاربر هیچ مسیری برای عبور ندارد.
- نام، شمارۀ تماس، متن شرح پرونده، ایمیل و شناسۀ کاربر **هرگز** ارسال نمی‌شود.
- بدون کوکی، بدون fingerprint، بدون اشتراک‌گذاری با شخص ثالث.
- ارسال با `credentials: "omit"` و `keepalive` انجام می‌شود تا کلیک روی لینک، رویداد را از بین نبرد.
- اگر مالک گیرندۀ رویداد را روی دامنۀ دیگری بگذارد، باید آن دامنه در `connect-src` سیاست CSP
  (`netlify.toml`) اضافه شود.

## پرسش‌هایی که با این طرح پاسخ می‌گیرند

1. کدام صفحات بیشترین «شروع فرم» را دارند؟
2. نرخ تبدیل (ثبت موفق ÷ بازدید صفحۀ تماس) چقدر است؟
3. کدام فیلد بیشترین خطای اعتبارسنجی را دارد (بدون دیدن مقدار آن)؟
4. چند درصد ارسال‌ها به «سرویس در دسترس نیست» می‌خورند؟

**توجه:** هیچ نرخی در گزارش‌ها یا ادعاهای سایت درج نمی‌شود تا دادۀ واقعی جمع نشود.
